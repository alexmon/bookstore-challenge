# Architecture Overview

## Design Patterns

- Domain-Driven Design (DDD) - Business logic organized around domain concepts
- Hexagonal Architecture (Ports & Adapters) - Clean separation between domain and infrastructure
- CQRS (Command Query Responsibility Segregation) - Separate read and write models
- Repository Pattern - Data access abstraction
- Aggregate Pattern - Consistent business rule enforcement
- SOLID Principles - Maintainable, testable, and scalable code


## Key Concepts

- separation of input sanitization from business validation
- use of ViewModel adapters
